# Caderno+ · PUCPR 2026/2

O Canvas da PUCPR melhorado. Projeto independente e não oficial, sem vínculo com a PUCPR nem com a Instructure (Canvas). (Antes chamado Campus+ e Quanto falta.)

Caderno+ é uma extensão do Chrome, Brave e Edge que roda dentro do Canvas da PUCPR (pucpr.instructure.com):

- **Próximos 7 dias:** no painel do Canvas, a próxima avaliação, a média, as matérias e uma linha do tempo com as entregas e provas de todas as matérias, com o que foi entregue, o que atrasou e quanto você precisa em cada prova. Marque uma tarefa como feita (✓) e ela fica cinza, sai dos lembretes e conta no progresso da semana; a marca fica só no seu computador.
- **Busca (Ctrl+K ou ⌘K):** em qualquer página do Canvas, procura matérias, tarefas e itens dos módulos de todas as matérias e abre com Enter.
- **Avisos:** os avisos de todas as matérias num lugar só, com os não lidos marcados.
- **Lembretes:** notificação 1 dia e 1 hora antes de cada entrega que falta, e na véspera e no dia de cada prova.
- **Tema escuro** (ou igual ao sistema).
- **Quanto falta:** em cada card e em cada matéria, quanto você precisa tirar nas próximas avaliações, com os pesos dos Planos de Ensino. As regras ficam em um arquivo por turma (`rules/<semestre>/<turma>.json`), reconhecida pelo número da matéria no Canvas. Turmas com regras: <!--TURMAS-->Ciência da Computação, manhã, 2026/2 ([`rules/2026-2/cc-manha.json`](rules/2026-2/cc-manha.json))<!--TURMAS-->. Em outras turmas o Caderno+ mostra a semana, os avisos, os lembretes das tarefas do Canvas e os arquivos, sem as notas; turmas novas entram como um arquivo em `rules/` (veja [Adicionar uma turma](CONTRIBUTING.md#adicionar-uma-turma)). Depois de 31/01/2027 as regras de 2026/2 saem do ar até a versão do próximo semestre. Não é oficial: "garantido" vale pelas notas lançadas, sem frequência nem recuperação.
- **Arquivos:** baixa os arquivos da matéria organizados em `Downloads/PUCPR/<matéria>/<tipo>/`.
- **Ícone:** os dias até a próxima prova.
- **Calculadora completa** (o módulo Quanto falta: meta, calendário, notas à mão, backup): no item **Caderno+** do menu lateral do Canvas, já com as notas lidas; o botão "Abrir no Caderno+" de cada matéria abre direto nela.

Cada parte pode ser desligada no botão da extensão; o botão "Atualizar agora" faz a próxima página do Canvas ler tudo de novo. Num computador compartilhado, as notas da calculadora ficam separadas por usuário do Canvas. O Feedback abre uma issue pública no GitHub: não escreva nome, RA nem notas. Sem senha, sem token e sem servidor: tudo fica no seu navegador ([privacidade](https://falta-quanto.vercel.app/privacidade.html)).

**Instalar:** baixe o zip em https://falta-quanto.vercel.app, descompacte, abra `chrome://extensions`, ligue o modo do desenvolvedor e use "Carregar sem compactação" na pasta.

**Sem extensão?** O [favorito](https://falta-quanto.vercel.app/#favorito) mostra a semana, os avisos e quanto falta na página do Canvas. O site serve só para baixar a extensão ou o favorito.

## Para quem desenvolve

Caderno+ for PUCPR 2026/2: a Chrome MV3 extension that runs on the PUCPR Canvas, plus a static site that only offers the download, the bookmarklet and the privacy page. No backend; data stays in the extension's storage.

- `index.html`: the landing page (pitch, demo video, install, bookmarklet, FAQ). The bookmarklet source between the `/*CP-BM*/` markers is generated by `scripts/sync-bookmarklet` (the extension's page scripts in one function with an in-memory `chrome` stand-in; tested).
- `app.html`: the calculator source (not deployed). The `<script id="core">` block holds the course weights and pure math; `<script id="ui">` renders it. `scripts/sync-ext-core` copies it into the extension as `core.js`, `app-ui.js` and `app.html` (scripts as files, CSP `script-src 'self'`); `app-boot.js` hands it the last Canvas reading. Inside Canvas it opens on `#campus` (left-menu item) as a full-size frame.
- `tests/notas-test.js`: core block. `tests/extension-test.js`: manifest, permissions, collector, generated calculator page, site links. `tests/inside-canvas-test.js`: the extension on a mocked Canvas (fake DOM, mocked `chrome` and `fetch`).
- `tests/rules-test.js`: the validator against `tests/fixtures/rules-bad/`, a core built with two turmas, the draft without grades. `tests/rules-golden.js`: cc-manha's numbers (`tests/golden/cc-manha.json`, captured before the rules became data) stay identical.
- `scripts/verify`: exit 0 = the test files and `scripts/check-rules` pass, generated files are current, every extension file and the UI script parse.
- `scripts/snapshot`: copy `app.html` into `old/` before any redesign.
- `extension/`: the Caderno+ extension. Load unpacked from `chrome://extensions` for testing. Files:
  - `prefs.js` (settings defaults) and `theme.js` (dark theme) run at `document_start`; `collect.js`, `core.js`, `files.js`, `content.js` at `document_idle`. Both groups share one content-script scope, so no top-level name may repeat.
  - `content.js`: dashboard panel (week from `/api/v1/planner/items` plus our exams; announcements), card pills, course panel, files download, reminders list. Panels are shadow-DOM, built with `textContent` only.
  - `background.js`: downloads (Canvas URLs only, into `Downloads/PUCPR`), reminder alarms and notifications, the icon badge.
  - `popup.*`: settings per module, the last reading time, buttons to open the calculator or Canvas, and "Atualizar agora" (marks the last reading old; the next Canvas page reads again).
  - Turma and term: the rules are data, one pack per turma in `rules/<term>/<turma>.json` (format and pt-BR field docs in `rules/schema.json`; `scripts/check-rules` validates weights, dates, ids and Canvas ids). `scripts/sync-rules` (run by `scripts/sync-ext-core`) embeds the latest term's packs between the `/*RULES*/` markers of the core, so nothing is fetched at runtime. The core builds `COURSES`, `CANVAS[subject].cids` and `SHORT` from them; `subjectOf` pairs a Canvas course by id (name prefix only for data without ids: old backups, old exports); `coursesFor(reading)` is the student's turma for the calculator page. Students of other turmas see only the note "O Quanto falta ainda não tem as regras da sua turma."; a contribution flow inside the extension is planned (SPEC.md, phase 9). Subject ids are unique across the term's packs (storage keys and backups use `subject:item`). `TERM` ("2026 / 2", the collector's filter) and `TERM_END` ("2027-01-31") come from the packs; after `TERM_END` the grade parts hide.
  - Canvas calls per page: the user is confirmed before any reading is shown (the id in the page, `ENV.current_user_id`, else one `/users/self`); another user's reading is dropped first; login/logout pages forget the reading. The reading is cached 10 min and one tab reads at a time ("refreshing" lock, 1 min). Dashboard with one course: cold 5 calls (was 6), or 4 with the id in the page; warm 1, or 0 with the id (was 1); reading over 10 min old 5, or 4 with the id (was 6).
  - The calculator's `localStorage` key carries the Canvas user inside the extension (`storageKey`, with a one-time move of the old unkeyed value).
  - History: since 0.7 it runs on `pucpr.instructure.com` pages (`content.js`): a status pill on each dashboard card, a panel on course pages with the next assessments and what each needs, a files download into `Downloads/PUCPR/<course>/<kind>/` (`files.js`, rules from the PUCPR bot's `canvas_files.py`), and the days to the next exam on the icon (`background.js`).
  - 1.0 renamed it Campus+ (1.0.5: **Caderno+**), a Canvas improvement where the grade calculator is one module: the week (Canvas planner deadlines plus our exams) and all announcements on the dashboard, reminders (`notifications`, alarms 1 day and 1 hour before), a dark theme (`theme.js`, document_start), and a settings popup to turn each part off (`prefs.js`, `chrome.storage.local` "prefs").
  - `extension/core.js` is generated from `app.html`'s core block by `scripts/sync-ext-core`; `tests/inside-canvas-test.js` fails when it is stale.
- `tools/canvas-export.py`: optional path for students who prefer their own Canvas API token; runs locally, read-only, prints the same JSON as the extension for the paste box. Stdlib only. Token from `CANVAS_TOKEN`, a `.env` (copy `tools/.env.example`; `.env` is git-ignored) or a hidden prompt.
- `scripts/package-extension`: builds the release zip; `EXT_LATEST` in `app.html` must match `extension/manifest.json` (tested).
- `video/scene.html` + `scripts/render-video`: render `media/demo.mp4` frame by frame with headless virtual time (needs ffmpeg); the scene is a mock Canvas tab running the real `content.js` (dashboard panel, then the "Caderno+" menu item opening the real `app.html`, then a course page) on stubbed `chrome.*` and Canvas API with made-up data, served over localhost. `FRAMES="ms …"` renders single review frames; `STILL=1` renders the store screenshots.
- `referencias/`: design reference links (`README.md`, `links.html`); not deployed.

Deploy: Vercel project `faltaquanto`, domain https://falta-quanto.vercel.app, serves only `index.html`, `privacidade.html` and `media/` (`cleanUrls`) with the headers in `vercel.json` (`.vercelignore` whitelist); `/app` and `/calendario` redirect to `/`. Production deploys need Enzo's approval each time.
